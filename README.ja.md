# ローカル環境で動作する Video Dubbing

[繁體中文](README.md) · [English](README.en.md) · **日本語**

中国語で録画したデモ動画に英語の吹き替えを付けられます。英語の動画を中国語に吹き替えることもできます。動画処理、音声認識、翻訳、音声合成はすべて手元の PC で行います。初回のインストールとモデルのダウンロードにはインターネット接続が必要です。

初版の対応範囲は、話者が 1 人で、長さが 5 分以内、サイズが 1 GiB 以下の動画です。動画をアップロードし、翻訳の方向を選んで音声認識と翻訳を実行します。各文を校正してから吹き替えを生成し、MP4 と 2 種類の SRT をダウンロードします。中国語への翻訳では繁体字と台湾の用語を使うよう指示しています。製品名、数値、専門用語は校正時に確認してください。

現在はプロトタイプです。Windows 上の Ollama（`qwen3.5:4b`）、WSL、RTX 4050 Laptop GPU の環境で中国語と英語の両方向の吹き替えを一通り実行し、MP4、原文字幕、翻訳字幕を生成できることを確認しました。同じ Wi-Fi に接続した iPhone からページを開けることも確認済みです。iPhone でのアップロード、再生、ダウンロードは一連の動作確認が残っています。現在の起動スクリプトでは `gemma4:e2b` と GPU 上の `medium` を使用しており、この組み合わせでの一連の動作は未検証です。

## 1. メイン環境のセットアップ（WSL / Ubuntu）

作業ディレクトリがまだない場合は、リポジトリを取得します。

```bash
git clone https://github.com/adombciha/video-dubbing.git ~/video-dubbing
```

WSL のターミナルで以下を実行します。`~/multi-agents` とは別の仮想環境を使用します。

```bash
cd ~/video-dubbing
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
sudo apt update
sudo apt install -y ffmpeg
WHISPER_MODEL=medium python dubbing.py download-asr
```

`venv` がない場合は、先に `sudo apt install -y python3-venv` を実行します。`start.sh` は faster-whisper の多言語モデル `medium` を使用するので、上記の手順で先にモデルの重みをダウンロードしてください。

GPU で音声認識を行うには、メイン環境に CUDA 12 用の cuBLAS と cuDNN 9 もインストールします。

```bash
.venv/bin/python -m pip install nvidia-cublas-cu12 'nvidia-cudnn-cu12>=9,<10'
```

`start.sh` はこの 2 つのパッケージのライブラリパスを自動で設定します。[faster-whisper の GPU セットアップ手順](https://github.com/SYSTRAN/faster-whisper#gpu)

## 2. CosyVoice 3 専用環境のセットアップ

CosyVoice の公式依存パッケージはメインアプリとバージョンが異なるため、`.venv` とは別の Python 3.10 環境にインストールします。以下の例ではインストール済みの `uv` で環境を作成します。音声モデルと GPU 用パッケージのダウンロード容量が大きいため、インストールには時間がかかることがあります。

```bash
cd ~/video-dubbing
sudo apt install -y git build-essential sox libsox-dev
mkdir -p vendor models
git clone --recursive https://github.com/FunAudioLLM/CosyVoice.git vendor/CosyVoice
uv venv --python 3.10 .venv-cosyvoice
uv pip install --python .venv-cosyvoice/bin/python --index-strategy unsafe-first-match -r vendor/CosyVoice/requirements.txt
uv pip uninstall --python .venv-cosyvoice/bin/python deepspeed
```

この手順では CosyVoice 公式の依存パッケージを使用します。[CosyVoice 公式インストール手順](https://github.com/FunAudioLLM/CosyVoice#install)

公式のリストには PyTorch、Microsoft、PyPI など複数のインデックスが含まれます。`unsafe-first-match` を指定すると、優先インデックスに互換性のあるバージョンがない場合に、uv が後続のインデックスも検索します。たとえば PyPI にある `protobuf==4.25` が優先インデックスに遮られて見つからない事態を防げます。このオプションはインデックスをまたいだ検索の制限を緩和するため、今回の公式リストのインストールに限って使用し、グローバル設定には追加しません。[uv の公式ドキュメント](https://docs.astral.sh/uv/pip/compatibility/#packages-that-exist-on-multiple-indexes)

PyTorch、CUDA、DeepSpeed のインストールに失敗した場合は、エラーメッセージをすべて保存し、まず `nvidia-smi` を確認してください。メイン環境のパッケージを無理にダウングレードする必要はありません。vLLM の追加インストールも不要です。

このプロジェクトで使用するのは標準の PyTorch 推論です。DeepSpeed による学習や高速化は使用しません。公式リストからは DeepSpeed もインストールされるため、その後に専用環境から削除します。これにより、Transformers が DeepSpeed をインポートする際に未インストールの CUDA コンパイルツールを要求するのを防ぎます。DeepSpeed を削除しても PyTorch はそのまま残り、CUDA を使用できます。今後、上流プロジェクトの DeepSpeed 学習を実行する場合は、別の環境と CUDA Toolkit を用意してください。

モデルをダウンロードします。

```bash
.venv-cosyvoice/bin/python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download(
    'FunAudioLLM/Fun-CosyVoice3-0.5B-2512',
    local_dir='models/Fun-CosyVoice3-0.5B',
)
PY
```

インストール後、環境を単独で確認できます。

```bash
cd ~/video-dubbing
COSYVOICE_PYTHON="$PWD/.venv-cosyvoice/bin/python" WHISPER_MODEL=medium .venv/bin/python dubbing.py check --offline
```

ソースコードとモデルの既定のパスは、上記の配置先に対応しています。`check --offline` はパッケージ、Whisper のモデルキャッシュ、CosyVoice のパス、依存パッケージのインポートを確認します。次の手順で Ollama を設定したら、画面の「環境状態と接続の確認」（「環境狀態與連線檢查」）でモデル一覧を確認できます。GPU 推論と音声品質の確認には、実際に吹き替えを生成する必要があります。

## 3. Windows 上の Ollama

プログラムは接続設定を `~/multi-agents/.ai-company/config.json` から読み取り専用で参照します。`start.sh` で翻訳モデルは `gemma4:e2b` に固定されます。Windows 上で Ollama を起動し、タグが完全に一致するモデルをインストールしておく必要があります。

Windows のターミナルでモデル一覧を確認します。

```powershell
ollama list
```

モデルはインストール済みで、テキストチャットと JSON 形式の出力に対応している必要があります。Ollama モデルの自動ダウンロードや削除は行いません。プログラムは `/api/tags` を使ってモデルを確認し、`/api/chat` で翻訳します。翻訳後はモデルのアンロードを要求し、その後の音声合成に備えて GPU メモリの使用量を抑えます。

`gemma4:e2b` と `gemma4:latest` は別のタグです。Windows の IP アドレスが変わった場合は、`OLLAMA_URL` で接続先を上書きできます。

短文の翻訳を速めるため、翻訳リクエストではまず thinking を無効にします。モデルがこの設定に対応していない場合は、既定のモードに戻します。バッチごとにセグメント数、番号、順序、訳文が空でないことを確認します。形式に誤りがある場合は、バッチごとに最大 1 回、修正を要求します。それでも失敗した場合は処理を停止し、不完全な結果は適用しません。

## 4. 起動と使い方

インストールとモデルのダウンロードが完了したら、以下を実行します。

```bash
cd ~/video-dubbing
./start.sh
```

スクリプトはプロジェクトの仮想環境を使い、翻訳には `gemma4:e2b`、音声認識には faster-whisper の `medium` を CUDA / FP16 で使用します。CosyVoice には専用環境を使用し、GPU ライブラリのパスも設定します。モデルとデバイスの設定は `start.sh` で固定され、ターミナルで事前に設定した同名の環境変数を上書きします。LAN からのアクセスも有効です。`./start.sh --port 7861` のように、メインプログラムの引数を後ろに指定できます。

使用中はプログラムを起動したままにし、終了するには `Ctrl+C` を押します。PC を再起動した後は、もう一度 `./start.sh` を実行してください。

PC で `http://127.0.0.1:7860` を開き、以下の手順で操作します。

1. MP4、MOV、M4V、MKV、WebM、AVI のいずれかをアップロードします。翻訳の方向を選び、「音声認識と翻訳」（「辨識與翻譯」）を押します。
2. 原文と訳文を校正します。原文を修正した後、「修正した原文で再翻訳」（「依修正原文重新翻譯」）を押すと、現在の訳文が上書きされます。
3. 既定では、動画の最初の発話区間から最大 12 秒を参照音声として使用します。この区間が 3 秒未満の場合や、雑音が多い、または無音区間が長い場合は、3〜15 秒の明瞭な音声を別途アップロードしてください。自分の声か、使用許可を得た素材のみを使用してください。
4. 「吹き替え動画を生成」（「產生配音影片」）を押します。プログラムが生成した音声の長さを測り、割り当てた時間を超えた場合は Gemma に訳文を短くするよう依頼し、超過したセグメントだけを再生成します。自動修正は最大 2 回です。成功すると、実際に使用した訳文が校正表に反映されます。更新された内容を確認してください。修正後も時間内に収まらない場合は、手動調整が必要なセグメントと秒数が表示されます。
5. MP4、翻訳 SRT、原文 SRT をプレビューまたはダウンロードします。SRT は独立したファイルで、映像への焼き込みは行いません。

翻訳時に各セグメントの長さと、訳文の語数または文字数の目安をモデルに渡します。吹き替えの長さは生成後に実測します。音声を合わせるときは元のセグメントの開始時刻を維持し、まず次の発話までの空き時間を使い、必要に応じて最大約 1.2 倍まで再生速度を上げます。それでも収まらないセグメントは、実測した長さをもとに訳文をさらに短くしてから吹き替え音声を再生成します。処理時間が長くなったり、言い回しが変わったりすることがあります。完了後に更新された訳文を確認してください。2 回の修正後も時間を超える場合は出力を中止し、音声の途中での切り捨てや重ね合わせを防ぎます。

吹き替え処理ごとに、短縮前の原文と訳文を `render-*/original-segments.json` にバックアップし、再生成した音声は `retry-1/` と `retry-2/` に保存します。吹き替え処理全体が成功した時点で、ジョブの訳文と校正表を更新します。失敗時には今回入力したテキストが残るため、修正して再試行できます。翻訳字幕には最終的な訳文が入り、表示時刻は実際の吹き替え音声に合わせて調整されます。

CosyVoice は 1 回の吹き替えジョブでサブプロセスを 1 つだけ起動します。モデルと参照音声の特徴量はそれぞれ 1 回準備し、再生成時にも再利用します。各ラウンドの音声生成後に、モデルの重みと参照音声の特徴量を RAM に移し、PyTorch の未使用 GPU キャッシュを解放してから Gemma で訳文を短縮します。次のラウンドではモデルの重みを GPU に戻します。モデルを保持する分の RAM が必要で、GPU ドライバー自体が使用する GPU メモリは残ることがあります。正常完了、失敗、タイムアウトのいずれでもサブプロセスは終了します。次の吹き替えジョブではモデルを再度読み込みます。音声認識は引き続き別のサブプロセスを使い、画面から同時に実行できるモデル処理は 1 件です。

処理時間の記録は、各出力の `render-*/cosyvoice-timing.jsonl` にあります。`torch_import`、`cosyvoice_import`、`model_load`、`reference`、文ごとの `speech`、`park_cpu`、`resume_gpu`、Gemma の `shorten` にかかった秒数が記録されます。サブプロセスの出力の全文は、同じディレクトリの `cosyvoice.log` にあります。同じ動画で速度を比較する場合は、初回の読み込み時間と再生成の全ラウンドを含めてください。テストの模擬モデルでは RTX 4050 の実際の速度は測れないため、通常の WSL ターミナルで検証する必要があります。

元の動画は上書きされません。動画のコピー、文ごとのテキスト、吹き替え音声、完成した動画は `data/jobs/job-*/` に保存されます。吹き替えを再試行すると新しい `render-*` ディレクトリが作成され、以前の結果も残ります。これらのデータは自動では削除されません。プログラムを停止してから、不要なジョブのディレクトリを手動で削除できます。

## 5. 同じ Wi-Fi に接続した iPhone で使う

`start.sh` では LAN からのアクセスが有効です。

```bash
./start.sh
```

Safari で `http://<Windows の LAN 側 IPv4 アドレス>:7860` を開き、「写真」や「ファイル」から録画済みの動画を選びます。動画の処理は PC 上で行います。ダウンロード後は Safari のダウンロード一覧からファイルを開き、iOS のメニューで保存または共有できます。

LAN から WSL に接続する方法は Windows / WSL のネットワークモードによって異なります。Windows 上では開けるのに iPhone で開けない場合は、WSL のミラーネットワーク（mirrored networking）、Windows ファイアウォール、ポート転送を確認してください。`--host 0.0.0.0` だけでは接続できない場合があります。

iPhone で開く URL には、Windows が接続している Wi-Fi またはイーサネットの IPv4 アドレスを指定します。iPhone 上での `127.0.0.1` は iPhone 自身を指し、`0.0.0.0` はサーバー側の待ち受け設定です。まず Windows PowerShell で、現在デフォルトゲートウェイが設定されているインターフェイスを確認します。

```powershell
Get-NetIPConfiguration | Where-Object { $_.IPv4DefaultGateway } | Select-Object InterfaceAlias, @{Name='IPv4';Expression={$_.IPv4Address.IPAddress}}
```

それでも接続できない場合は、通常の WSL ターミナルでネットワークモードと WSL の IP アドレスを確認します。以下は設定を読み取るコマンドです。

```bash
wslinfo --networking-mode
hostname -I
```

NAT モードでは、Windows から `localhost` 経由で WSL 上のページを開けても、通常は iPhone から接続するために Windows 側のポート転送とファイアウォールルールが必要です。ミラーモードでは LAN からの接続を直接受け付けられますが、ファイアウォール設定は確認してください。実際のモード、IP アドレス、ブラウザーのエラーを確認してから TCP 7860 を対象に対処し、ファイアウォール全体の無効化は避けてください。[Microsoft の WSL ネットワーク解説](https://learn.microsoft.com/en-us/windows/wsl/networking)

ログインが必要な場合は、`DUBBING_USERNAME` と `DUBBING_PASSWORD` を設定できます。公開共有リンクは使用しないでください。起動時は常に `share=False` です。信頼できる証明書を指定して HTTPS を有効にできます。

```bash
./start.sh --ssl-certfile /path/to/cert.pem --ssl-keyfile /path/to/key.pem
```

現在は標準のカメラアプリで録画した動画をアップロードする方式です。Safari のページ内からカメラへのアクセスを要求することはなく、ネイティブアプリや PWA としても提供していません。

## 6. 3 言語対応のリアルタイム字幕バー（Windows Chrome）

先にポート 7860 を使用しているサービスを停止してから、字幕モードを起動します。

```bash
cd ~/video-dubbing
./start.sh --live
```

**Windows 版 Chrome** で `http://127.0.0.1:7860` を開きます。

1. 「Chrome タブ」（「Chrome 分頁」）または「システム音声」（「系統音訊」）を選択し、元の音声の言語と字幕の言語を設定します。繁体字中国語、英語、日本語に対応しています。
2. 「翻訳を開始」（「開始翻譯」）を押します。Chrome でキャプチャするタブまたは画面全体を選び、「音声を共有」（「分享音訊」）をオンにします。選択したソースから音声トラックを取得できない場合は、選び直すよう案内が表示されます。
3. 音声の共有を確定すると、細長い字幕バーが自動で開き、最前面に表示されます。Chrome でフローティングウィンドウが開かない場合は、メインページで音声を取り込むか、「フローティング表示」（「懸浮置頂」）を押して手動で開けます。
4. ステータスが「音声を取り込み中」（「正在收音」）になってから、ソースを再生します。フローティングバーには訳文、ステータス、停止ボタンが表示されます。メインページでは原文と処理時間も確認できます。元のタブは開いたままにしてください。フローティングバーを閉じると、音声の取り込みも停止します。
5. 「取り込みを停止」（「停止」）を押すと、取り込み済みのセグメントを処理し終えてから音声とモデルを解放し、ツールバーを元のタブに戻します。

`start.sh` は WSL が NAT モードの場合、現在の Windows 側のゲートウェイを Ollama の接続先に使います。ミラーモードでは `127.0.0.1` を使用します。別の Ollama に接続する場合は `OLLAMA_URL` を指定できます。手動設定が優先されます。

このモードはマイクを経由せずにデジタル音声トラックを直接取得し、字幕を生成します。「タブの音を消してキャプチャ」（「分頁靜音擷取」）をオンにすると、そのタブの音声が手元で再生されないよう Chrome に要求します。動画プレーヤー自体の音量をゼロにすると、取り込み元の音声トラックまで無音になることがあります。システム音声を取得できるか、ミュートしても音声トラックが残るかは Chrome、Windows、再生アプリによって異なるため、短い動画で先に確認してください。吹き替え音声は生成しません。

音声を約 3 秒分ためてから、次に 0.6 秒のポーズがあった時点で認識に送ります。発話が続く場合は 1 セグメントあたり最大約 5 秒で区切ります。その後、音声認識と翻訳にも時間がかかります。短い発話をまとめることで推論の繰り返しを減らせますが、短文の最初の字幕は少し遅れて表示されます。「取り込みを停止」（「停止」）を押した場合は、3 秒未満の残りの音声も認識に送ります。

このモードも faster-whisper の `medium` を使います。CUDA では `int8_float16` を使用し、取り込みを開始するたびにモデルを 1 回読み込みます。リアルタイム認識ではデコードを 1 回だけ行い（`beam_size=1`、`best_of=1`、`temperature=0`）、タイムスタンプは生成しません。信頼度の低いセグメントの再デコードを避けられる一方で、雑音が多い場合や聞き取りにくい発話では、認識精度が下がることがあります。音声の取り込み中は Gemma の `gemma4:e2b` をメモリ上に保持します。事前読み込みの前後と各翻訳の前に、Ollama の `/api/ps` から実際のコンテキストサイズを取得して再利用します。モデルを共有する他のアプリとの間で設定が頻繁に切り替わるのを防ぐためです。同名モデルの設定値が正の整数の場合に限り採用し、初期値は 2048 です。初回の準備には時間がかかります。CosyVoice は起動しません。

メインページの上部に、セグメントごとの音声の長さ、音声認識にかかった秒数、翻訳にかかった秒数、処理速度が表示されます。処理速度は「音声の長さ ÷ 当該セグメントの処理時間」です。`1×` を超える場合は、そのセグメントの再生より速く処理できたことを示します。音声がたまるまでの待ち時間、初回の読み込み、キューでの待ち時間は計算に含まれません。連続再生中に速度が長時間 `1×` を下回ると、処理が再生に追いつかないことがあります。処理待ちの音声が 3 セグメントたまると、字幕の遅延が増え続けるのを防ぐために自動で取り込みを停止し、取り込み済みのセグメントを処理します。セグメント分割と模擬モデルのテストで確認できるのはリクエスト数と計時の挙動です。実際の速度と認識品質は、同じ内容を GPU で処理して比較する必要があります。

Ollama が出力の繰り返しを検出して中断した場合（`token repeat limit reached`）、プレーンテキストと低い temperature で 1 回再試行します。再試行も失敗した場合は、該当セグメントに翻訳失敗と表示し、原文を表示したうえで次のセグメントを翻訳します。

Ollama を共有するバックグラウンドジョブも、キュー待ちの原因になります。ローカルの RTX 4050 6 GB で `medium` と `gemma4:e2b` を使って短文をテストしたところ、同じ約 3.8 秒の英語音声で、Hindsight のバックグラウンドサービス稼働中にセグメント全体の処理に 7〜23 秒かかったことがあります。そのサービスを一時停止した後、3 回の音声認識と翻訳の合計時間はそれぞれ 0.94 秒、0.75 秒、0.81 秒で、そのときのモデル準備には約 25 秒かかりました。これは短い英語音声での観測結果です。長い音声や中国語・日本語での品質と速度は未検証です。処理時間にばらつきがある場合は、Ollama を呼び出す他のアプリやサービスも確認してください。

字幕サービスは既定でローカルからの接続のみを受け付け、同じユーザー名とパスワードの設定を使用します。タブやシステム音声のキャプチャには、デスクトップ版 Chrome のセキュアコンテキスト（localhost または HTTPS）が必要です。iPhone の通常の LAN 内 HTTP URL ではこのキャプチャモードを使用できません。動画をアップロードして吹き替える場合は `./start.sh` で起動します。ポート 7860 や GPU メモリの競合を避けるため、起動するモードはどちらか一方にしてください。

## 設定

以下は Python を直接実行するときの既定値です。普段 `start.sh` を使う場合は、翻訳モデルが `gemma4:e2b`、音声認識モデルが `medium`、音声認識デバイスが `cuda` に設定されます。CosyVoice 用の Python には、プロジェクト内の `.venv-cosyvoice/bin/python` を使用します。

| 環境変数 | 既定値 / 用途 |
| --- | --- |
| `OLLAMA_URL` | `multi-agents` の設定を使用。設定がなければ `http://localhost:11434` |
| `OLLAMA_MODEL` | `multi-agents` の設定を使用。設定がなければ `gemma4:latest` |
| `WHISPER_MODEL` | `small`。ローカルモデルのパスも指定可能。切り替え後は先に `download-asr` を実行 |
| `ASR_DEVICE` | `auto`。`cpu` または `cuda` も指定可能。CPU は int8、CUDA は float16 を使用 |
| `COSYVOICE_PYTHON` | メインプログラムと同じ Python。上記の手順でインストールした場合は `.venv-cosyvoice/bin/python` を指定 |
| `COSYVOICE_ROOT` | `vendor/CosyVoice` の絶対パス |
| `COSYVOICE_MODEL_DIR` | `models/Fun-CosyVoice3-0.5B` の絶対パス |
| `FFMPEG` / `FFPROBE` | PATH 上の `ffmpeg` / `ffprobe`。実行ファイルのパスを指定可能 |
| `DUBBING_OUTPUT_DIR` | プロジェクト内の `data/jobs` |
| `DUBBING_USERNAME` / `DUBBING_PASSWORD` | 任意。指定する場合は両方を設定 |

`auto` は、CUDA デバイスを検出できるかどうかだけで音声認識のデバイスを選びます。cuDNN / CUDA ライブラリに互換性がない場合はエラーになります。その場合はまず `ASR_DEVICE=cpu` で一連の処理を確認できます。Ollama の翻訳品質、声の再現度、アクセント、処理速度は使用するモデルとハードウェアに左右されます。元の感情や声質を完全に再現できるとは限りません。

音声認識のワーカーは、FFmpeg が変換した 16 kHz モノラルの PCM16 WAV を直接読み込み、正規化した音声サンプルを Whisper に渡します。これにより、再デコードや、PyAV のバージョンによって音声を開く際の引数が異なる問題を避けられます。

## 検証

```bash
python -m pytest -q
python dubbing.py check
```

単体テストでは、翻訳セグメントの欠落、誤った番号、双方向の翻訳プロンプト、テキストの校正、時間の重複、吹き替え音声の尺超過、無音、字幕、元ファイルの保持を確認します。訳文の自動短縮テストでは、尺を超えた文だけが再生成されること、自動修正が 2 回までであること、元の訳文がバックアップされること、失敗時にユーザーが入力したテキストが残ること、校正表と字幕が同期することを確認します。FFmpeg の結合テストでは、実際に動画を生成し、速度調整、合成、再生時間の確認を行います。FFmpeg / ffprobe がない場合は、その旨を示してテストをスキップします。テスト用に人工生成した音声を使うため、モデルの品質確認は別途必要です。

旧版では短文と無音区間を含む 30 秒のサンプル動画 2 本を実測し、中国語から英語への吹き替えに約 455 秒、英語から中国語に約 445 秒かかりました。別の 17.4 秒の動画では、リクエスト送信から最初の文の生成完了まで、初回の吹き替えで約 238 秒、再生成時に約 221 秒かかりました。これらはモデル再利用の導入前の結果です。新版にはモデルの再利用、参照音声のキャッシュ、RAM と GPU の間での切り替えを追加しました。実際にどれだけ速くなったかは、同じ動画と新版の処理時間の記録を使って検証する必要があります。進捗のパーセンテージは処理段階を示します。残り時間の見積もりには使えません。また、短文や無音区間のあるサンプルの所要時間を比例計算して、より長いデモ動画の所要時間を推定することはできません。

実際の動作確認では、1 人で話す 30 秒以上の中国語動画と英語動画をそれぞれ 1 本用意し、以下を確認してください。

- 製品名、数値、単位に誤訳がなく、文の抜けもない。
- 吹き替え音声が聞き取れ、文末の途切れや音声の重なりがなく、画面上の操作と説明が一致している。
- 完成した動画を PC と iPhone で再生でき、字幕ファイルを開ける。
- Ollama に接続できない場合や、動画に音声がない、または動画が破損している場合に、内容が分かるエラーが表示され、元の動画も保持される。

このバージョンは、リップシンク、複数話者の分離、背景音の分離に対応していません。リアルタイム字幕モードではリアルタイムの吹き替えは行いません。動画を吹き替える際は元の音声トラック全体を置き換えるため、背景音楽や操作音も取り除かれます。
